# Guided study plan (10 hours per week)

This schedule is an ambitious introduction to Python security engineering. Mastery takes longer and depends on project feedback. Adjust pace based on tests and depth, not calendar alone.

## 12-month plan
| Month | Python knowledge | Security context | Deliverable |
|---|---|---|---|
| 01 | syntax, types, conditionals, functions | threat modeling/ethics | 10 tested small programs |
| 02 | lists, dicts, sets, strings, bytes | log format basics | event frequency counter |
| 03 | files, exceptions, modules, typing | integrity/evidence | file manifest tool |
| 04 | OOP, unit tests, CLI | OS permissions and automation | packaged inventory CLI |
| 05 | sockets, IP, TLS, HTTP | local network diagnostics | local checker + report |
| 06 | async, generators, binary parsing | offline PCAP analysis | bounded traffic analysis |
| 07 | SQLite, JSONL, times, regex | SOC detection | time-window login detector |
| 08 | cryptography and safe APIs | authn/authz, TLS, secure storage | local secure API exercise |
| 09 | schemas, CI, dependency management | AppSec/DevSecOps | secure code review and CI |
| 10 | specialized parsers, analysis | malware triage/DFIR | static file triage + timeline |
| 11 | large data and SDK patterns | TI/cloud/endpoint logs | offline intel normalizer |
| 12 | integration/testing/reporting | incident response capstone | mini SOC and final report |

## Weekly rhythm
- Day 1: 60 min concepts + 30 min notes.
- Day 2: 90 min guided code.
- Day 3: 90 min independent code.
- Day 4: 60 min reading source docs + 30 min debugging.
- Day 5: 90 min tests and edge cases.
- Day 6: 120 min lab, experiment and written findings.
- Day 7: 60 min retrospective or rest/adjustment.
Total: 10 hours when completed as scheduled.

## Suggested quarterly gates
- Q1: confident with pure Python, functions, safe parsing and basic testing.
- Q2: safe CLI, local network clients, binary data and concurrency.
- Q3: SOC analytics and secure APIs with meaningful regression tests.
- Q4: defensible investigation/reporting, integration and public portfolio.

## Review rubric (0–4 each)
1. Correctness and test quality.
2. Input validation and safe failure modes.
3. Code readability, typing and packaging.
4. Privacy, authorization and bounded resource use.
5. Evidence, documentation and honest limitations.

20/20 is not required; repeat a module if critical safety or correctness is weak. Prefer showing well-tested code and a thoughtful write-up over accumulating certificates.
